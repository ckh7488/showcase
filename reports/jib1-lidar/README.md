# JIB1 라이다 분석 — 공개 정적 뷰

`index.html`에서 네 개의 분석 화면으로 이동한다. 라이브 센서나 분석 EXE를 실행하지 않고 저장된 결과를 표시한다.

| 화면 | 보존한 기능 |
|---|---|
| `replay.html` | 7개 로그 × 30묶음, 원본/XYZ/Cluster, 센서 선택, 5ms ON/OFF, 거리 후보 |
| `point-origin.html` | BODY/JIB 전체 위치, 원본 점 P/Q의 패킷·채널, 모델 각도 비교 |
| `calibration.html` | 두 캘리브레이션의 같은 원본 점, 전체 모델, 정합/EXE 각도 선택 |
| `packet-border.html` | 세 자료 조건 × 30묶음, A/B/C, 1/5묶음, raw/XYZ, 동기화된 시점 |

현장 BODY 경보와 별도 재현 JIB 경보의 미대응, 근사 시각, 캘리브레이션의 남은 오차 등 기존 한계를 유지했다. 개인 이름이 포함된 사진, 절대 PC 경로, 사용하지 않는 운영 설정, 원본 통신 로그·PCAP와 EXE는 포함하지 않는다.

## 저장 형식

300개 점군 파일을 묶음 단위 `.bin`으로 저장한다. 같은 XYZ 12바이트를 한 번 저장하고 각 배열의 순서를 uint32 인덱스로 보존한다. 점 좌표와 인덱스를 byte plane으로 정렬한 뒤 zlib로 압축한다. 좌표 양자화, 다운샘플링, 보간은 하지 않는다. 분류 바이트도 별도로 무손실 압축한다.

파일 시작의 little-endian uint32는 UTF-8 JSON 헤더 길이다. 헤더의 `lengths` 순서로 zlib 블록이 이어진다. 첫 두 블록은 좌표 pool과 인덱스이며 이후는 분류 등 부가 배열이다. `packed-data.js`가 선택 묶음을 fetch하여 복원한다. 모든 참조는 상대 경로이며 일반 정적 웹 서버에서 동작한다.

재생과 캘리브레이션이 동일한 점군을 사용하므로 보고서 폴더 하나 안에서 데이터를 공유한다. 총 점군 저장량은 1,849,605,980 → 772,488,360바이트다. 각 파일의 SHA-256과 확인 수는 `data/packing-audit.json`에 있다.

원본 JS 자료에서 재생성하려면 저장소의 `scripts/pack_lidar_frames.py`에 입력 data 폴더와 이 보고서의 data 폴더를 넘긴다. 생성 단계에만 NumPy가 필요하다. 사이트 실행에는 Python/Node가 필요 없다.
